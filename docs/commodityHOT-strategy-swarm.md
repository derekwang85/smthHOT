# commodityHOT 前瞻性规划 · 资深商品交易/研究员视角 + SWARM 对抗分析

- 版本：v0.2（战略规划稿 · SWARM-enhanced）
- 视角：**跳出执行者，站在一个成熟有能力的 Commodity Trader / Research 的内行角度**
- 方法：先由资深交易员视角给出初稿 → 5 个利益冲突角色独立攻击 → 魔鬼代言人攻共识 → 冲突保留式合并 → 输出前瞻建议
- 说明：本机 swarm.py 因无可用 LLM API key 与本地 chat 模型（仅有 bge-m3 嵌入模型），无法直接调用工具脚本；改用**同方法的内部五阶段对抗**执行，设计哲学与 derekcoding 框架 method/13 一致。

---

## 阶段 0 · 交易员的身份与"我想要什么"

开篇先诚实：大多数 commodity 新闻聚合站（SMM/生意社/Fastmarkets/Mining.com/RSS 水文站）都对**交易决策没有增量价值**。原因不是内容少，而是内容没有"为决策排序"。一个真金白银交易的人，每天早晨打开一个页面，真正想要的是：

1. **"今天是什么日子"** —— 有没有会改变我头寸的事件（矿山停产/罢工/库存拐点/TC 骤降/政策突变）。
2. **"信号有没有叉"** —— 现货端（升贴水/库存）与盘面（近远月结构）是否在互相验证或背离。
3. **"这个信息可信吗"** —— 一手 vs 转述 vs 营销，谁在说，当事人自己说了没。
4. **"对哪个品种/哪个合约有影响"** —— 是铜精矿还是阴极铜？LME 还是 SHFE？近月还是远月？
5. **"所有人都知道了吗"** —— 老消息 vs 新信息。能被价格提前反映的新闻，读了也没用。

而 commodityHOT 目前的形态（把 AIHOT 换成信源）天然有一个**错位**：AIHOT 服务"AI 从业者了解趋势"，commodityHOT 若照搬，会沦为一个"商品新闻 RSS"，而不是"交易员的情报台"。这就是要解决的问题。

## 阶段 1 · 资深交易员初稿：commodityHOT 应该长什么样

（以下是"我"作为成熟 trader 脑子里希望看到的：功能、内容、布局。先不全盘考虑可行性，把愿望写全。）

### 1.1 核心功能诉求（按交易决策价值排序）

**A. 事件优先，而不是"新闻流"**
- 首页不是"最新文章列表"，而是一个**"今日影响清单"**：列出三四件真正改变供需/库存/价格结构的事件，每条标注影响品种、方向（利多/利空/中性）、影响强度判断、涉及合约。
- 反例是我现在对 SMM 的恨：一天几十条"沪铜上涨 X%"、"现货贴水收窄"，没有一条回答"那然后呢"。

**B. 品种中心，而不是文章中心**
- 以品种（铜/铝/锌/铅/镍/锡/金银）为一级导航，每个品种页 = 该品种的"一页情报":
  - 最新价格与结构（近月/远月、back/contango 状态）
  - 交易所库存 + 变化
  - 现货升贴水
  - 矿山/冶炼事件时间线
  - 政策相关
  - 多篇报道已归组的事件本体
- 让交易员"打开铜页"一眼看到"铜今天发生了什么变动"，而不是在海量文章里翻。

**C. 时间差与"新信息"标注**
- 每条事件标注**首次发现时间**与**原文发布时间**——如果发现时价格已经跳了，标"价格已反映，注意兑现"；如果还没动，标"潜在预期差"。
- 这是交易员最想要的但目前所有聚合站都不做的：**区分"旧闻"与"增量"**。

**D. 升贴水、结构、库存的数据层（不是可选的增值，是命根子）**
- 纯新闻无法支撑交易决策；真正值钱的是"期货结构 + 库存 + 现货升贴水"三位一体。commodityHOT 至少要能：
  - 采集/推送三大交易所（LME/SHFE/COMEX）库存与周报
  - 现货升贴水（SMM 或交易所报价）
  - 由数量（库存绝对水平）与结构（近月升水/贴水）推导"平衡紧/松"的边际判断
- 这部分必须走 `external` 推送或 `json_list`，模型只解读、不计算（框架已经保证）。

**E. 多语言但"一句话给到结论"**
- 采多语言没问题，但**最终给交易员的是中文结论**，且结论要"答案先行"——先把影响说清楚，再给原文链接。
- 法/俄/西/葡/荷不是凑数；俄语源对镍/铝制裁链、西语源对智利/秘鲁供给是**一手信源**，比英文媒体转述快半步。

### 1.2 内容布局（页面层）

- **首页** = 今日影响清单（Top 事件）+ 品种罗盘（各品种当日热力 ICON）+ 宏观温度计（美元/利率对金属的传导）+ 数据日历（本周要出的库存/产量/海关数据）。
- **品种页** = 上述 B 的一页情报。
- **事件页** = 归组后的完整叙事：时间线 + 多方口径 + 一手优先 + 对供需的量化影响（如有）。
- **数据页** = 库存/升贴水/价差的历史与边际变化（可作为低价位数据大屏）。
- **观点页** = 分析师多空 + 重磅研报摘要（克制、带标记）。

### 1.3 三条"反共识"主张（初稿里可能过激的）

1. **弱化"全市场新闻"**，强化"今日 3-5 件影响事件"——数量少但每条值钱。
2. **数据优先于文字**：库存/升贴水数字 > 分析师观点；模型只做解读不做预测。
3. **给交易员"预期差"排序**，而不是"热度"排序——AIHOT 的"多少人讨论"对交易员是逆向指标（人声鼎沸往往已见顶）。

## 阶段 2 · 五个利益冲突角色的独立攻击

> 角色由 orchestrator 按"利益冲突"动态生成——不是互补，是**互相拆台**。五个角色看过初稿后各自写"我不同意且你这么想会死"的理由。

### 角色 A · 宽覆盖优先派（"别做窄，做全"）
**反对点：** 你把 commodityHOT 做成"今日 3-5 件事件"，等于把一个**信息差生意**做成了"编辑精选"。Trade 不是每天都有大事件——多数日子是低波动、没新闻的，你做"今日影响清单"大部分早上是空的或硬凑，用户会流失。反例：Bloomberg/Bloomberg Terminal 不是靠"少而精"，是靠**全面覆盖 + 终端搜索**；你需要"全"打底，"精选"只是锦上添花。
**暗伤：** 你假设交易员"时间稀缺"，但成熟交易员其实**有专用终端（BBG/路透）**，他们不缺信息、缺的是**整合**。commodityHOT 的差异化不该在"更少"，而在"更完整的相对更便宜的整合"。

### 角色 B · 数据工程派（"你的数据层是空中楼阁"）
**反对点：** 你说"库存/升贴水是命根子"，但这恰恰是 commodityHOT **最没有能力做**的部分。三大交易所库存、现货升贴水是**付费数据源**（SMM/lombard/Fastmarkets 是按 API 收费的），你既没有授权，也可能违反反爬。模型"只解读不计算"很好，但**没有数据可解读**。没有数据层的 commodityHOT = 又一个新闻 RSS；要做真正的数据层，成本/合规风险你没算。
**暗伤：** 你让"数据优先"，但项目当前的采集能力是"rss/web_list/json_list"，**没有交易所数据网关**。你要么加付费数据依赖，要么退化成"新闻站"。

### 角色 C · 合规与信源信用派（"你正在把转载风险吹成卖点"）
**反对点：** 把"升贴水/库存/价格数据"作为卖点，等于做主承自营商品报价的再分发——这是**版权和监管雷区**（SMM 数据条款、交易所数据授权、转售限制）。当前框架的"默认只显示摘要+原文链接"是**安全的设计**，你却在密谋打开全文/数据。国外交易所（LME）的"现金结算价"、库存每日仓单都有明确的分发许可限制。
**暗伤：** 你的"一页情报"若聚合了 SMM 的升贴水但没授权，commodityHOT 会因**数据版权**被下架，而不是死于流量。

### 角色 D · 终端体验派（"交易员不可能用你的网页做情报台"）
**反对点：** 现货交易员用 Bloomberg Terminal、Eikon；投研用 Wind/CMC。commodityHOT 若定位"我比终端更懂你的品种"，是**用业余挑战专业**。你需要承认：对**专业交易员**，你永远不可能是主屏。你的真实机会是**次级受众**（现货企业采购/销售/风控、研究助理、小型交易者、产业链从业者），他们对"一页情报"更饥渴、更买得起"整合但非实时"。
**暗伤：** 目标客户画错了。你服务的是**泛产业链+中小实体**，却按**顶级 desk trader**的标准设计，会两头不讨好：太专业、太缺数据终端的深度；太抽象、不如 SMM 的行情直给。

### 角色 E · 反热度主张派（"你的预期差排序是伪命题"）
**反对点：** 你说"弱化热度、强化预期差"，但**预期差恰恰无法预先判断**——只有事后才知道价格反映了没有。你做不出"什么还没被 price in"的机器；你只能事后标注"price 已反映"。这会误导交易员去追已经定价的行情，比没有这个功能更糟。
**暗伤：** 你把一个**无法可靠实现的谦逊能力**（识别预期差）当卖点；更稳的是诚实标注"信息时效"（几点首发、价格当时反应了多少），把预期差判断**留给人**，别让模型装神。

## 阶段 3 · 魔鬼代言人（攻击"逐渐形成的共识"）

共识正在成形于"数据优先 + 品种中心 + 展示实时性 + 服务泛产业链"。魔鬼代言人对**这个共识**自身发起攻击，专找大家一起犯的盲点：

1. **大家都在假设"采集到就有价值"，没人攻击"采集到的噪音会把信号掩埋"。**
   聚合站最大的敌人不是"缺内容"，而是"同质信息通胀"——同一件事，LME 公告、Mining.com、SMM、X 上四个人，被抓成 5 篇。你的"归组"是事后聚类，但交易员要的是**在通胀中只看到 1 条**。若 commodityHOT 首页还是"今天 40 条"，你就和其他站没区别。→ **真正的护城河是"事件去重 + 一手优先 + 一句结论"，而不是来源多。**
2. **没有人算"这份东西到底为谁省了什么钱"。**
   "一页情报"很美，但成熟交易员已有 SMM + 自己的 Excel + 电话。commodityHOT 若不能提供**他们本地没攒好的 cross-check**（跨品种/跨市场联动、制裁链传导、库存与结构背离提醒），就没有抓手。你的价值定位必须从"给你信息"升级为"给你信息间的交叉比对"。→ 商品交易的 Alpha 在**关联与背离**（铜镍价差、LME-SHFE 价差、库存与升贴水背离），这恰恰是机器能做、单个 trader 懒于做的。
3. **大家默认"多语言是差异化"，但没人攻击成本与噪音。**
   法/俄/西/葡/荷 5 种小语种 = 5 套信源维护 + 5 套翻译质量兜底 + 更高的误判/误导风险。若只为"少数几个镍/铝交易员"做俄语源，ROI 存疑。→ 多语言应是**"定点补强"**（俄语只盯 Nornickel/铝制裁、西语只盯 Codelco/智利），而不是"全语种铺开"。
4. **整个方案的致命盲点：没有商业模式，只有功能清单。**
   这是规划最该被问的：commodityHOT 靠什么活？如果免费，谁来养信源成本；如果付费，凭什么让现货企业付费？功能再多，没有"付费抓手"（数据日历、独家题材、事件提醒推送、企业内参）就是公益项目。→ 前瞻规划必须把"变现路径"和功能路线绑在一起设计。

## 阶段 4 · 辩论（专家互相反诘，接触面扩大）

把 A/B/E 三派当代表拉一场简短辩论，看各自对共识的动摇：

- **E 对 A**："你坚持全量覆盖，但覆盖越全、与 SMM/Wind 越同质，commodityHOT 就越没有打开理由。商品信息已经够多，缺的是少而准。"
  - **A 反驳**："'少而准'只在有大事时成立。你的'今日影响清单'在风平浪静时会空窗两周，用户习惯建立不起来。可以'全量打底 + 顶部精选'，而不是非此即彼。"
  - **E 承认一半**："可以，但'全量'必须是**去重后的全量**，不是 40 条重复转载。" → 共识修正为：**全量去重打底（数据目录式），Top 影响事件精选置顶（编辑式），两者叠层。**
- **B 对 D**："数据网关是核心竞争力，也是成本黑洞；web 页面做不出终端深度。"
  - **D 回应**："所以主打受众不是 desk trader，是现货采购/风控/中小机构。他们对终端的**订阅门槛**望而却步，commodityHOT 用'网页整合 + 每日推送'就能切进去。数据门槛用'读取公开/授权摘要 + external 自抓'渐进解决，不做 Bloomberg 级 tick。"
  - **B 坚持**："但'渐进'意味着很长一段时间没有数据层，这段时间 commodityHOT 就是个新闻站，先发优势被 SMM 吃光。" → 承认：**数据层要作为 P0-P2 优先项之一，不是 P5 收尾。第一周至少跑通 LME/SHFE 库存摘要 + 升贴水快照的 external 通道。**

辩论结果：共识从"数据优先 + 品种中心"收敛为三个**必须同时成立**的支柱：
1. **去重的全量情报目录**（覆盖全，但不通胀）——打底
2. **今日影响事件精选**（Top 3-5，带品种/方向/时效）——置顶
3. **逐步建立的数据层**（库存/升贴水/价差，先公开摘要后授权）——根

## 阶段 5 · 冲突保留式合并（不作平均，保留分歧，输出前瞻方案）

> 合并不是把五派意见取中，而是**保留冲突作为风险信号**，给出一个**承认分歧的、分层的、可演进**的建议方案。

### 明确的共识（可用于落地）

1. **目标客户修正**：commodityHOT 的**首要用户不是顶级 desk trader，而是现货产业链人员（采购/销售/风控）、中小机构、研究助理**。话术设计按他们的痛点来（"省下每天盯 40 个窗口的时间"），而非按 desk trader 的终端对标。
2. **三个内容支柱（缺一不可）**：
   - **全量去重目录**：所有信源照收照归组，但同事件在首页只出现 1 条（一手优先）。
   - **今日影响清单**：置顶 3-5 件"改变供需/价格结构"的事件，每条标品种、方向、时效（首发时间 vs 原文时间）、涉及合约。
   - **数据模块**：从 P0 就开始做库存/升贴水/价差的"摘要级"数据，模型只解读不计算。
3. **多语言 = 定点补强，非全语种铺开**：俄语只配 Nornickel/制裁链条，西语只配 Codelco/智利秘鲁供给，法语只配非洲铜钴，葡语只配巴西，荷语只配欧洲鹿特丹升贴水。每个小语种**必须有明确交易理由**才进。
4. **诚实的时间标注，不吹"预期差"**：标注"首发时间/原文时间/价格当时反应"，把预期差判断留给人。魔鬼代言人这条被采纳为**不可省略的诚实边界**。

### 保留的冲突（不强行调和，转为风险与特性设计）

- **全量 vs 精选**：结论 = 叠层，不二选一；但"精选置顶的品牌识别"需要在 A/B 测试后定，避免头部编辑压过数据目录的客观性（冲突 A×E）。
- **数据层深度**：何时从"摘要级"升级到"付费全量"（B 主张尽快、合规派主张稳），**未决** → 列为 P3 决策点，取决于授权谈判与成本模型。
- **是否做实时推送**：交易员真身要 tick，但现货企业要的是"日度+异动提醒"；初版**只做"异动阈值推送 + 每日一份"**，不做秒级。（D 派坚持，A 派可接受，B 认为推送要先有数据。）

### 前瞻性路线（含商业模式，补上魔鬼代言人指出的大洞）

| 阶段 | 产品重点 | 商业化验证 |
|---|---|---|
| **P0 骨架** | 站名/分类/信源首批(中英免费源) | 无 |
| **P1 情报台** | 全量去重 + 今日影响清单 + 品种页 | 验证留存：日活/回访（免费） |
| **P2 数据根** | LME/SHFE 库存摘要 + 升贴水快照 external 通道 + 数据日历 | 数据页 Premium 预告 |
| **P3 授权/升华** | 付费数据源授权、延迟 tick、异动提醒推送 | **变现入口：订阅"情报台"** |
| **P4 多语种定点** | 俄/西/法/葡/荷 定点信源 | 国际化 B 端线索 |
| **P5 企业内参** | 自定义品种组合、限定渠道推送、导出一页 PDF | **B 端 SaaS：按企业/按用户订阅** |

**最终一句话（保留魔鬼代言人的清醒）：**
commodityHOT 不是"给顶级交易员的终端"，而是"让产业链上的每个普通人，用得起、看得懂、省时间的有色金属情报台"。它的三根支柱——去重全量、今日影响、诚实数据——必须同时立住，且从第一天就为"付费抓手"预留位置，否则它只是一个比 SMM 更新慢的新闻 RSS。

# 第二部分 · 前瞻决策点的深挖与 SWARM 可行性判定

> 上一轮战略分析收敛出 5 个待 Derek 拍板的决策点。本部分对每个决策点做：问题拆解 → 候选方案 → **局部 SWARM 对抗判定可行性**（造冲突角色 → 魔鬼代言 → 冲突保留合并 → 结论）→ 明确建议。每个决策点的 SWARM 均独立执行，最终结论进入第三部分 Roadmap。

---

## 决策点 1 · 目标客户：服务谁？（现货产业链 / 中小机构 vs 顶级 desk trader）

### 1.1 问题拆解
战略阶段"终端体验派"提出了尖锐质疑：顶级 desk trader 有 Bloomberg Terminal / Eikon / Wind，commodityHOT 永远成不了他们的主屏。因此"为谁设计"决定了 UI 密度、内容颗粒度、数据深度、乃至是否要做秒级 tick。这不是偏好问题，是产品生死问题。

### 1.2 候选方案
- **方案 A：主打现货产业链从业者 + 中小机构**（采购/销售/风控/研究助理/小型交易团队）。定价"整合但非实时"，日报 + 异动提醒，网页友好。
- **方案 B：主打 top desk trader**。对标终端深度，秒级数据、复杂价差矩阵、Ticker 化界面。成本极高、与 BBG 正面竞争。
- **方案 C：双层**——公共层服务产业链（免费日报/精选），付费层服务中小机构（深度数据 + API + API 推送）。bandicoot 两种都留，但资源按付费层倾斜。

### 1.3 SWARM 判定（3 角色 + 魔鬼代言 + 合并）
**角色 B1（终端死亡论）**：做 top desk 等于拿网页打高盛 Bloomberg，死路。交易员要 tick 级、要自建模型导出、要一手 API——这些 commodityHOT 成本上做不到，做了也是对牛弹琴。**可行性：方案 A/C 可，B 不可。**

**角色 B2（付费意愿论）**：现货采购/风控最痛的不是"信息不够"，是"信息散落在 SMM/微信群/供应商电话里"。他们愿意为"整合 + 每日一句结论 + 异动告警"付费，因为没有替代品（BBG 对他们太贵）。但注意：供应链从业者对"价格数据准确性"零容忍，错一个数就流失。**可行性：A 最顺，C 的 API 层对中小机构成立，但要有数据准确 SLA。**

**角色 B3（自嗨陷阱论）**："主打产业链"听着谦逊，但可能变成"谁都不满足"——拓扑 trader 嫌你慢，产业采购嫌你数据少。别忘了战略阶段"反热度派"说的：**护城河在去重 + 一手优先 + 交叉比对**，这本来就不依赖目标客户是谁。只要这三根支柱在，天然更贴近产业链（他们要的是省时间），所以不必刻意分两层。**可行性：A 最聚焦，C 分散。**

**魔鬼代言人攻击共识（共识倾向 A）**：
- 共识是"服务产业链/中小企业"，但**没人验证这群人真的有付费预算**。很多现货企业采购/销售是"信息当成本"而非"当投资"，未必愿意订阅。→ 需要 P1 用免费日报先验证回访留存，再看谁愿意付。
- "不做 top trader"是正确认怂，但**别完全放弃专业界面的一个子集**：研究助理/初级分析师恰恰需要"终端式但便宜"的界面，这是 A 与 B 之间最甜的缝。→ 方案 C 的"API 层"其实服务的就是这群人，不必全砍。
- 财务可行性没算：产业链客户客单价低、需量大；desk trader 客单价高但获客难。**免费 vs 付费的转换漏斗**才是真正要设计的，不是二选一。

**冲突保留式合并结论**：**采方案 C 的方向，但阶段化执行**——**P0–P1 按方案 A 完全聚焦产业链/中小企业打造体验与留存；P2 起在数据层落地后，为研究助理/中小机构开放"轻量 API + 延迟数据"的付费入口（方案 C 的收敛版，不做 tick，做"整合+延迟"），不碰 top desk（方案 B 明确放弃）。** 同时魔鬼代言人的"付费意愿验证"吸收为 P1 的关键验收指标（见 Roadmap）。

## 决策点 2 · 编辑精选 vs 数据目录：内容权重怎么分？

### 2.1 问题拆解
战略阶段两个"反共识"主张打架：宽覆盖派要"全量打底"（避免空窗期），反热度派要"今日影响清单"（避免噪音通胀）。上一轮辩论收敛为"去重全量 + Top 影响 叠层"。本决策点要定的是：**首页的视觉与算法权重、编辑介入度、以及"什么算 Top"的规则**。

### 2.2 候选方案
- **方案 A：编辑置顶优先**——首页 60% 空间给"今日影响清单"（人工/模型挑选 3–5 条），30% 给数据概览，10% 给全量目录入口。强编辑，强观点，品牌感强。
- **方案 B：数据目录优先**——首页就是"品种罗盘 + 库存/升贴水变化表"（客观、结构化、无编辑），Top 事件作为右侧栏。「数字自己会说话」。
- **方案 C：按场景自适应**——交易日早盘默认数据目录（交易员查结构），午后/异动时自动切到事件清单（有大事才置顶）。引擎判断"今天有没有值得置顶的事件"，没有就退回目录。

### 2.3 SWARM 判定（3 角色 + 魔鬼代言 + 合并）
**角色 D1（数据客观论）**：交易员重建信任，"编辑精选"= 第二手判断，容易背锅（推了错方向）。数据表是中性的、可验证的、不怕质疑。首页必须默认数据目录。**可行性：B 最稳，A 有信任风险。**

**角色 D2（编辑价值论）**：纯数据目录 SMM 也有，没有差异化。真正值钱的是"今天哪 3 件事值得知道"——这是 commodityHOT 相对一切静态数据站的灵魂。编辑/模型精选不是背锅，而是**筛选 + 排序 + 一句影响**，这正是"省时间"的抓手。**可行性：A/C 有灵魂，B 泯然众人。**

**角色 D3（漏斗冷静论）**：新用户第一次来，看到"今日影响清单"会觉得"哦这站有想法"（留人）；老用户天天来，要的是"库存变了没"（留存）。所以**首屏用编辑精选建立品牌，常驻用数据目录维持高频**。两者不是二选一，是"引流 vs 留存"分别负责。**可行性：C 的上限最高。**

**魔鬼代言人攻击共识（共识偏向 C/自适应）**：
- "自适应"很聪明，但**引擎怎么判断"今天有没有大事"？** 若模型误判（没大事时硬推、有大事时漏推），比固定布局更伤信任。→ 自适应需要明确的触发门槛（如"评分≥X 的事件数>0"），且默认值偏向目录，宁可不推不硬推。
- 大家默认"编辑精选=好"，但**是谁在做这个编辑？** 若靠模型精选而无人工复核，战略阶段"反热度派"批评的"预判预期差失败"风险会重演。→ Top 清单的入选规则必须是**可解释的**（显式触发因子：库存突变/TC骤降/官方公告/停复产），不是模型一句"这个重要"。
- 信任争议没解决：数据错了怎么办？编辑推错了怎么办？→ 每个 Top 事件必须**锚定原文 + 数据来源 + 时效**，让用户能自己验证，商品也不能把"判断"外包给黑盒。

**冲突保留式合并结论**：**采方案 C（场景自适应），但加严魔鬼代言人的两个护栏**：
1. **Top 清单用"显式触发因子"驱动**（库存/升贴水/TC/价格的阈值变化、T1 官方公告、停复产关键词），可解释、可复核，不靠模型模糊的"重要"。
2. **默认态偏向数据目录**，只有触发因子命中且事件评分超过门槛才置顶事件清单；没大事时首页就是干净的品种罗盘 + 数据表。
3. 每个 Top 事件卡片**必须带原文链接 + 数据来源 + 首发/原文双时间戳**——把"判断的正确性"留给用户复核，commodityHOT 只做"排序与聚合"（呼应战略阶段的诚实边界）。

## 决策点 3 · 数据层：从 P0 就做 external 通道，还是先靠授权摘要？

### 3.1 问题拆解
战略阶段"数据工程派"指出的硬伤：commodityHOT 的三支柱里，"诚实数据"是为交易员提供真价值的关键，但**库存 / 升贴水 / 价差是付费授权数据**（SMM、Fastmarkets、LME、交易所数据许可）。当前采集器只有 `rss / web_list / json_list / external`，没有交易所数据网关。做不做数据层、做到多深、用 free 公开摘要还是付费授权，决定成本、合规、和"凭什么让用户付费"。

### 3.2 候选方案
- **方案 A：纯公开摘要启动**——只用交易所/协会官网免费公布的日度库存、官方报价、周报 PDF 摘要，`web_list` + `external` 抓取，模型解读。0 授权费，但数据颗粒粗、可能有延迟、依赖官网格式稳定。
- **方案 B：external 通道早期搭网关**——自写采集脚本抓 LME/SHFEN/COMEX 的公开库存与仓单、SMM 的每日现货均价摘要，经 `POST /api/ingest/items` 推送，带正确时效。数据更结构化成库，仍是"公开可用"范围。
- **方案 C：付费授权全量**——购买 LME/SMM/Fastmarkets 数据 API，拿到 tick/延时全量 + 授权再分发。数据最完整，但成本高、涉及转售协议、上线周期长。

### 3.3 SWARM 判定（3 角色 + 魔鬼代言 + 合并）
**角色 E1（合规先行论）**：方案 C 的"库存/升贴水再分发"吃掉一半是版权雷区。SMM 数据条款、LME 数据许可、交易所每日仓单都有明确分发限制；"免费开局、量大了再授权"的侥幸心理会埋雷。**所以初版必须走公开可引用的来源（交易所官方公告、协会公开数据、官网自报），方案 A/B 合规，C 滞后到有法务确认。可行性：A/B 可，C 需前置合规。**

**角色 E2（数据即护城河论）**：方案 A 的"公开摘要"SMM 自己也有，没有差异性。commodityHOT 要想让"数据目录"成为付费理由，必须做出 **SMM 没有的整合层**——比如"LME+SHFE+COMEX 三所库存一张表、跨市场 back/contango 同屏对比、库存 vs 升贴水背离提醒"。这些用**公开数据也能做**，靠的是"整合聪明度"而非"独家数据源"。**可行性：A/B 够用，关键在整合，不在独家。**

**角色 E3（成本现实论）**：方案 C 订阅费+开发+转售合规，ROI 对"主打产业链/中小客户"不划算（客单低）。**初版用公开数据把整合跑通、证明有需求，再决定要不要为真正的付费层去买授权**。别在最没验证的时候先砸钱。**可行性：A 起步、B 扩展、C 缓行。**

**魔鬼代言人攻击共识（共识倾向 A/B + 整合）**：
- 共识是"用公开数据 + 整合"，但**没人算"公开数据的准确性维护成本"**：官网改版、字段变动、节假日停更、时区错位，都是持续的运维黑洞。若数据错了没人发现，三支柱里"诚实数据"最先垮。→ 需要"数据健康度"机制（上次成功抓取时间、字段空值率、跨源一致性抽查）。
- "整合聪明度是护城河"听着对，但**SMM 完全有能力抄你的整合**。你的真正时间是"数据目录+今日影响+去重"三支柱的**协同**，单独一根（哪怕整合）都防不住复制。→ 别把护城河只押在"整合"上。
- 合规派说要"引用公开来源"，但**"link to source" 不等于 "can republish figures"**。即使走公开来源，"转述几个百分比"和"整表再分发"边界要按具体来源条款逐一定，不是一刀切"公开=自由"。→ 每个接入的数据源要做**授权分级记录**（可引用摘要 / 可展示表格 / 只可链接）。

**冲突保留式合并结论**：
1. **P0 起就搭建 external 数据通道（方案 B 的架构），但数据只取"公开可引用摘要"（方案 A 的内容）**——合规 + 有数据骨架 + 为后续升级留口。
2. **差异化押在"三所整合 + 结构对比 + 背离提醒"（SMM 没做好的协同层），不押独家数据源。**
3. **每个数据源建立"授权分级"标签**（引用/展示/链接三档），合规可审计。
4. **内置"数据健康度"机制**：抓取时间戳、字段空值、跨源一致性抽查，运维可监控。
5. 方案 C 的付费全量**推迟到 P3，且以"已证明整合有付费需求"为前提**，不再是最早投入。

## 决策点 4 · 多语言：定点补强（俄镍/西铜…）还是 7 语种铺开？

### 4.1 问题拆解
战略阶段魔鬼代言人指出："全语种铺开"= 5 套信源维护 + 5 套翻译质量兜底 + 更高误导风险；多语言应是"定点补强"而非差异化口号。但用户明确提到法/俄/西/葡/荷都想覆盖。本决策点要定：**补哪些语种、补什么品种/题材、各语种信源的交易理由**。

### 4.2 候选方案
- **方案 A：全语种并行铺开**——法/俄/西/葡/荷 全部首批接入对应媒体。
- **方案 B：定点补强**——只为有明显"一手交易理由"的语种配信源：
  - 俄语 → Nornickel（镍/钯/铜）、俄罗斯铝业 RUSAL、制裁与断供新闻（一手、快）
  - 西语 → Codelco / 智利 / 秘鲁 / 厄瓜多尔铜矿（全球铜供给核心）
  - 葡语 → 巴西（铝土、铁合金、淡水河谷关联）
  - 法语 → 非洲铜钴带（刚果金 / 赞比亚）法语区媒体
  - 荷语 → 欧洲需求 / 鹿特丹货舱升贴水（欧洲金属物流枢纽）
- **方案 C：收纳 + 自适应**——信源全收，但"是否展示/是否置顶"由触发因子决定（该语种事件命中重大题材才稀释进来），平时低权重。

### 4.3 SWARM 判定（3 角色 + 魔鬼代言 + 合并）
**角色 F1（一手优先论）**：commodity 交易的钱在"别人没看到的一手"。刚果/智利/印尼/俄罗斯的**本地语一手**往往比英文媒体快 24–48h（英文是转述）。所以西（智利/秘鲁铜）、俄（镍/钯/铝制裁）、法（刚果钴铜）**是真实 Alpha 来源，必须收**。葡（巴西）/荷（欧洲）价值次之但可收。**可行性：西/俄/法强，葡/荷中。**

**角色 F2（质量崩塌论）**：7 语种 = 7 段翻译质量兜底。小语种模型翻译（尤其荷兰语）错误率高，"一句话影响"若翻错会直接误导交易动作，比没有更糟。**每加一个语种，就要一个人工复核样本的校准成本**。图省事全铺，等于没校准就说"我都会"。**可行性：建议先 3 语种（西/俄/法），跑顺再扩。**

**角色 F3（内容通胀论）**：commodityHOT 的护城河是"去重 + 少而准"。多语种最容易制造"同一件事 5 种语言的转载"，让去重难度暴涨、首页再次通胀。**多语种必须和去重引擎强绑定**：跨语言判重（title 翻译后归一化）必须先行，否则收语种越多越乱。**可行性：多语种的前提是跨语言去重先做好。**

**魔鬼代言人攻击共识（共识倾向 B/定点）**：
- 共识是"定点补强"，但**没人回答"第一批到底哪 2-3 个语种价值最高、其他延期到什么时候"**。建议：先西语（智利/秘鲁铜供给）+ 俄语（镍/钯/铝制裁）这两个"一手快半步"的，法语跟刚果钴铜、葡语跟巴西、荷兰语最后，形成**分阶段**而非"全都要"。
- "本地一手快半步"是真，但**快半步不等于净 Alpha**：本地语可信度、官方 vs 谣言混杂、节假日差异都会引入噪音与假信号。→ 本地语源要配**一手判定 + 交叉验证**（执法/公告/路透确认），不能裸奔。
- 没人算"维护 7 语种信源的持续成本"（官网改版、失效源、翻译校准）。**每个语种是个运维负担**，不是一次配置就完事。

**冲突保留式合并结论**：**采方案 B（定点补强）的分阶段版**：
1. **第一批只上 2 个强价值语种：西语（智利/秘鲁铜供给）+ 俄语（镍/钯/铝制裁断供）**，都配明确交易理由 + 一手交叉验证。
2. **法语（刚果钴铜）→ 葡语（巴西）** 作为第二批，跑顺去重与翻译质量后再进。
3. **荷兰语（欧洲升贴水）最后且可只用 `hot_signal`**（作热度证据，不抢精选）。
4. **跨语言去重引擎（标题归一化 + 同事件归组）是"多语种之前必须存在"的前提**（决策点 2 的触发因子里已含）。
5. 每个小语种信源要有"授权分级 + 一手判定 + 交叉验证"三要素才能进 editorial。

## 决策点 5 · 变现：免费情报台 → Premium，还是直接 B 端内参订阅？

### 5.1 问题拆解
战略阶段魔鬼代言人指出最致命空白：**整个方案只有功能清单，没有商业模式**。commodityHOT 靠什么活，直接影响 roadmap 优先级（要不要为 API 预留、要不要做企业内参、免费能撑多久）。这是"项目"升格为"产品"的分水岭。

### 5.2 候选方案
- **方案 A：免费情报台 → Premium 订阅（C 端/个人）**——核心情报免费拉留存；付费解锁：自定义品种组合、深度数据、优先推送、历史回溯。客单低需量大，靠免费→付费漏斗。
- **方案 B：B 端内参订阅（企业/机构）**——直接为企业采购/风控/研究部门提供"定制内参 + 专属渠道推送 + PDF 导出"，按席位/按接入收费。客单高但销售周期长、要靠样板客户。
- **方案 C：混合（推荐）**——免费公共层（情报台拉量、SEO、品牌） + B 端内参（主线变现） + 后续可开个人 Premium（长尾）。用免费公共层养数据与口碑，用 B 端订阅赚真钱。

### 5.3 SWARM 判定（3 角色 + 魔鬼代言 + 合并）
**角色 G1（免费漏斗论）**：商品领域信息泛滥，免费增值是主流获客。先免费把"今日影响 + 数据目录"做出口碑，用户回流够多再推付费，转化成本低、无销售团队也能跑。**可行性：A 稳，纯 B 冷启动难。**

**角色 G2（B 端价值论）**：产业链采购/风控"信息即成本"，企业愿意为"定制化 + 不依赖个人微信的稳定情报"付企业级价格。个人 C 端订阅付费意愿极低（大家都习惯白嫖 SMM 免费摘要），**靠 C 端订阅撑不起成本**。主线必须走 B 端。**可行性：B 利润厚，A 难养。**

**角色 G3（冷启动现实论）**：B 端销售要样板客户、要销售话术、要 POC，而 commodityHOT 现在连信源都没跑通。**初期纯 B 端会饿死**——必须在免费情报足够吸引人、有 2-3 个愿意当样板的企业后，B 端才成立。**可行性：混合 C，先免费后 B。**

**魔鬼代言人攻击共识（共识倾向 C/混合）**：
- 共识是"免费拉量 + B 端变现"，但**没人回答"免费的代价"**：免费用户越多，采集、调模型、带宽成本越高，若量上来了却不变现，成本反而成了雪球。→ 免费层要有成本意识：免费用户看"延迟数据 + 通用日报"，实时/定制/推送留给付费，天然控成本。
- "先免费后 B 端"听着顺，但**B 端需要的是"能证明行业 insight 的样板"**，不是"网友在用"。→ P0-P2 阶段就要定向找 2-3 个产业链企业当种子用户（他们可能不需要完整 SaaS，只需要"为你定制品种的那几页"），用他们的反馈打磨，而不是等大众留存。
- 没算提供什么"付费墙真壁垒"：若 B 端客户能自己抄 commodityHOT 的整合，付费就没有理由。→ 付费层要卖 SaaS 化能力（自动导出、定时推送、团队共享、历史回溯、告警规则），而不是"看得见的几页网页"。

**冲突保留式合并结论**：**采方案 C（混合），但要防魔鬼代言的四个坑**：
1. **免费公共层 = 口碑 + 数据 + SEO 入口**，但只给"延迟数据 + 通用日报"；实时/定制/推送/告警 = 付费。
2. **B 端内参是主线变现**，但走"种子企业（2-3 家样板）+ 定制品种页"验证，不靠大众留存自然转化。
3. 付费墙的壁垒是 **SaaS 能力**（自动导出、定时推送、团队协作、历史回溯、告警规则、自定义品种组合），不是"多几页网页"。
4. 免费→B 端之间不预设"个人 Premium"硬要现在做，等免费公共层量和 B 端样板都跑出后再评估。
5. 商业化节奏：P0-P2 免费情报台打磨 + 找种子；P3 上 SaaS 化 B 端入口；P4 多语种喂 B 端线索；P5 全面 B 端。

# 第三部分 · 最终 Roadmap（战略 + 全部决策点的落地闭环）

> 本 Roadmap 合并第一部分（战略）与第二部分（决策点 1-5 的 SWARM 结论），把 commodityHOT 从"改信源的网站"落成"有商业模式的有色金属情报台"。每个阶段含：目标 / 关键任务 / 决策点落地 / 商业化节点 / 验收指标。

## 总纲 · 三支柱 + 一底座（贯穿全程）
- **底座**：跨语言去重引擎（同一件事多语言只留 1 条，一手优先，标题归一化）——多语种和"少而准"的前提。
- **支柱 1**：全量去重目录（覆盖全但不同质）。
- **支柱 2**：今日影响清单（Top 3-5，显式触发因子驱动，可解释）。
- **支柱 3**：诚实数据层（LME/SHFE/COMEX 三所整合 + 升贴水/价差 + 背离提醒，公开可引用摘要起步）。

## P0 · 骨架（已可由 docs/customize.md 落地）
- 站名 commodityHOT / subject「有色金属」/ tagline（commodityHOT-plan.md §1 已定）。
- taxonomy.ts 8 类分类 + 标签 + 实体（§2），topics.json 三组主题（§3），features.ts 关 AI 模块（§4）。
- prompts/ 全量替换有色内容类型 + 五轴权重 + 术语规则（§5/§6），selection.ts 初版阈值 + gold 校准流程（§7）。
- sources.json 首批免费中英文信源（§8）。
- **验收**：typecheck / test / smoke 全过；首批免费源试抓成功；无付费源也能出内容。

## P1 · 情报台（对应决策点 1/2）
- **决策点 1 落地**：按方案 A 完全聚焦产业链/中小企业；UI 侧重"今日影响清单 + 品种页一页情报 + 数据概览"，去终端化。
- **决策点 2 落地**：首页默认数据目录（品种罗盘+库存/升贴水表），Top 影响清单由"显式触发因子"驱动，无大事不硬推；每个 Top 卡片带原文+来源+双时间戳。
- 引入跨语言去重引擎（即便 1.0 只有中英，也为多语言铺路）。
- **验收（魔鬼代言人加的付费意愿验证）**：免费日报回访留存曲线（D7/D14 回流率）、用户停留、是否有人主动问"你们有没有付费版"。

## P2 · 数据根（对应决策点 3）
- 搭建 external 数据通道（架构上是方案 B），数据只取公开可引用摘要（内容上是方案 A）。
- 实现「三所库存整合 + 结构对比 + 库存↔升贴水背离提醒」这一协同层（差异化核心）。
- 每个数据源建"授权分级"标签（引用/展示/链接三档）+ 数据健康度监控（抓取时间、空值率、跨源一致性）。
- **验收**：数据目录可出"三所库存一张表 + back/contango 同屏 + 背离提醒"；合规可审计。

## P3 · SaaS 化 B 端入口（对应决策点 5）
- 上"付费墙"：实时/定制/推送/告警/团队共享/历史回溯/自定义品种组合 = 订阅；免费层保持延迟数据 + 通用日报。
- 用 P1-P2 期间定向的 2-3 家种子企业打磨样板客户（按他们的品种定制那几页）。
- 可选：如数据整合已证明有付费需求，再评估购买付费授权（方案 C 前置条件是合规 + ROI 成立）。
- **验收**：首个付费样板客户；B 端试用→转化漏斗有数据。

## P4 · 多语种定点（对应决策点 4）
- 第一批：西语（智利/秘鲁铜供给）+ 俄语（镍/钯/铝制裁）——一手快半步，配交叉验证。
- 第二批：法语（刚果钴铜）→ 葡语（巴西）。
- 荷兰语用 `hot_signal` 只作热度证据。
- **验收**：每语种"授权分级 + 一手判定 + 交叉验证"三要素齐备；翻译质量抽检通过；去重引擎跨语言归组正确。

## P5 · B 端全面化（对应决策点 5 深化）
- B 端内参：企业定制内参 + 专属渠道推送 + PDF 导出 + 团队席位。
- 国际化 B 端线索（多语种喂到的海外企业/机构）。
- **验收**：B 端订阅成为稳定收入之一；免费公共层仍承担口碑/SEO 入口。

## 收官 · 一句话总结（合并全部 SWARM 的清醒）
commodityHOT 最终形态 = **"让产业链上的普通人用得起、看得懂、省时间的有色金属情报台"**：用**跨语言去重 + 显式触发的今日影响 + 公开数据的诚实整合**三支柱立住内容，用 **SaaS 化 B 端**立住商业，用**多语种定点补强**扩展一手信源。它不做 top 级终端的竞品，不做全语种的口号铺开，不在没验证需求前为付费数据砸钱——每一步都由 SWARM 判定过可行性，冲突被保留为风险信号而非抹平。
